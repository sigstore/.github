# AI Policy

This document outlines Sigstore's policy on AI (e.g., LLM, agent) contributions.

Any individual who contributes to the Sigstore project and plans to use AI must follow this policy.

## Summary

The Sigstore project allows for contributions made with AI. However, you must disclose the use of AI assistance.

All contributions, including but not limited to technical discussions, design documents, user documentation, and code,
must meet a consistently high quality bar. If a contributor lacks meaningful engagement in discussions
or submits unreviewed code, their contribution may be ignored or rejected without feedback.

For technical discussions, the Sigstore project expects active participation and engagement from humans, not AI.
You must not use AI to speak for you.

For technical contributions, if you use AI to produce code, you must understand the
code that you have produced. You should be ready to explain your technical choices if asked.

## Responsibility

You are responsible for all contributions to the Sigstore project, regardless of whether they were manually written or generated by AI.
You must fully understand any technical contributions or discussions as well as the existing codebase.
It is not acceptable to post on an issue or submit a patch that you cannot understand and explain yourself.
In explaining your contribution in pull request and issue descriptions, any AI usage must be to assist, not replace, your participation.

AI must not be used to automatically generate comments and interact with maintainers and other contributors.

You must respect maintainers' time by not overburdening them with unreviewed contributions.

## Disclosure

You are required to disclose whether AI has been used to assist in the development of technical contributions.
You must document the usage of AI tools. The Sigstore project reserves the right to close any issue or pull request
that does not include a disclosure if it is suspected to be authored by AI.

## Communication

When interacting with other contributors (e.g., on Slack, GitHub issues, pull requests), do not use AI to speak for you.
Human-to-human communication is essential for an open source community to thrive.

The Sigstore project strongly encourages participation in community meetings as well, especially for any larger contributions.

## Contribution Requirements

Contributors must follow these requirements when making technical contributions.

Maintainers and other trusted individuals are allowed to exercise their best judgment to bypass these rules.

### Open an Issue First

You must open an issue before submitting a PR, except when the change is small (e.g., a documentation change,
a minor and obvious bug fix). Include the motivation for the change and a brief outline of the change.

### Understand the Code

You must review any code before submitting a PR. You are responsible and held accountable for the contribution.

You must understand the code. Maintainers may ask questions about the technical choices made, and you, as the human,
are expected to be able to explain your decisions. Do not use AI to automatically reply to maintainers' questions.

### Prefer Small Patches

Keep changes as small as possible. Maintainers will be able to more quickly review and merge them.

### Sufficient Test Coverage

All changes must be accompanied by some form of testing, such as unit tests, integration tests,
or CLI example commands. For tests that are code, you must understand the tests and be able to explain
your choices to maintainers.

### Unacceptable Contributions

Sigstore maintains a high bar for technical contributions, especially with respect to security.
The Sigstore project will reject contributions that do not adhere to the requirements in this policy.

Examples of unacceptable contributions include but are not limited to:

* Large PRs. If a single PR is over 1000 lines of code, you must break it up into multiple PRs.
* Convoluted, distracting text in PR descriptions, commit messages, issues, or code comments that hurts readability and comprehensibility.
* Providing feedback on PRs or issues when you've made no contributions before.
* Changes without sufficient testing.
* Insecure code.
* Using AI to complete issues tagged as "good first issue". These issues are intentionally left for new
  contributors who are interested in getting involved and learning about the project.

### Licensing and Legal Requirements

All contributions must comply with the Sigstore project's licensing requirements. All code must be compatible with the Apache License 2.0.

### Signed-off-by and Developer Certificate of Origin

AI agents must not add Signed-off-by tags. Only humans can legally certify the Developer Certificate of Origin (DCO).
The human submitter is responsible for:

* Reviewing all AI-generated code
* Ensuring compliance with licensing requirements
* Adding their own Signed-off-by tag to certify the DCO
* Taking full responsibility for the contribution

## Enforcement

Failure to abide by these requirements may result in immediate closure of a pull request or issue,
and repeated or flagrant offenses may result in being banned from the organization.

If your contribution is incorrectly identified as AI-generated and noncompliant with the policy,
the Sigstore project encourages you to attend a community meeting to discuss your contribution.
